# API: engine/sprite

[← README](../README.md) · [core](api-core.md) · [world](api-world.md) · [scene и render](api-render.md) · [gpu](api-gpu.md) · [assets и entity](api-assets.md) · [sprite](api-sprite.md) · [prop](api-prop.md) · [rig](api-rig.md) · [anim](api-anim.md) · [physics](api-physics.md) · [script](api-script.md) · [video](api-video.md)

Частицы и парящий текст — одна подсистема, потому что геометрически это одно и
то же: плоский квад с альфа-вырезом, стоящий в мировом пространстве. Частица —
один такой квад, строка — по одному на глиф.

Ассеты необязательны: без них частицы рисуются плоским цветом, а текст —
встроенным шрифтом.

---

## Ключевое решение: билборд замораживается при сборке

Неймтег в Minecraft всегда развёрнут к камере. В трассировщике так нельзя:
у поверхности, которая переориентируется на каждый луч, нет согласованного
ответа для отражения и для теневого луча. Отражение в воде смотрит на квад
с другой стороны, чем камера, — и что он должен показать?

Поэтому `facing` и `aimAt` разворачивают квад **один раз, пока сцена
строится**, и замораживают. Дальше это обычная геометрия: отбрасывает тень,
попадает в отражение, участвует в GI. Выглядит как билборд, ведёт себя как
предмет.

```cpp
sprites.add(text::facing(font, "EMBER HALL", {-3, 12.5f, 0}, eye, style));
//                                                          ↑
//                              направление берётся здесь и больше не меняется
```

## sprite.hpp

```cpp
struct Sprite;
void aimAt(Sprite&, Vec3 target);
void aimAt(std::vector<Sprite>&, Vec3 target);
void orientationTowards(Vec3 direction, float& yawDegrees, float& pitchDegrees);
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `position` | — | Центр квада, в блоках |
| `size` | `1 × 1` | Ширина и высота, в блоках. Частица в игре — около `0.1` |
| `yawDegrees` | `0` | Поворот вокруг +Y |
| `pitchDegrees` | `0` | Затем вокруг повёрнутого +X |
| `rollDegrees` | `0` | Затем вокруг собственной нормали |
| `texture` | `nullptr` | Без неё квад заливается `tint` — этого хватает пылинке |
| `uvMin` / `uvMax` | `0,0` / `1,1` | Подпрямоугольник атласа: так один шрифт обслуживает все глифы |
| `tint` | `1` | Линейный цвет, умножается на текстуру |
| `emission` | `0` | Линейное излучение, может быть больше единицы |
| `roughness` | `1.0` | 1 — полностью диффузно |
| `alphaCutoff` | `0.5` | Ниже — тексель пропускает луч насквозь |
| `doubleSided` | `true` | Видно сзади: нормаль переворачивается, текстура читается зеркально |

Все нули у углов оставляют нормаль на **+Z** — той стороне, с которой на
сущность смотрят спереди. Соглашение то же, что у сущностей: см.
[соглашения](conventions.md#ориентация-сущностей).

> `aimAt` для вектора разворачивает **каждый спрайт вокруг своего центра**.
> Для частиц это ровно то, что нужно — у них нет общего направления чтения.
> Для текста это неверно, и поэтому текст поворачивается не так; см. ниже.

## sprite_set.hpp

```cpp
void clear();
void add(const Sprite&);
void add(const std::vector<Sprite>&);
void build();                    // построить BVH; без этого набор пуст для трассировщика

bool intersect(const Ray&, float maxDistance, SpriteHit&) const;
bool occluded(const Ray&, float maxDistance) const;
bool bounds(Vec3& lo, Vec3& hi) const;

const std::vector<Sprite>& sprites() const;
const Bvh& bvh() const;
```

Добавление уплощает спрайт в жёсткое преобразование сразу; дальше рендерер
видит только плоский список квадов — ровно как `EntitySet` показывает ему
плоский список коробок.

Отличие одно: спрайтов тысячи, поэтому список обходится через
[BVH](api-core.md#bvhhpp), а не сканируется. Именно поэтому дерево написано
безразличным к содержимому — `EntitySet` сможет взять его без изменений, когда
персонажей станет достаточно, чтобы это понадобилось.

**`build()` обязателен.** Несобранный набор не даёт попаданий — он инертен, а
не опасен, но и не виден. Любое `add` после сборки её сбрасывает.

```cpp
SpriteSet sprites;
sprites.add(motes);
sprites.add(text::facing(font, "LABEL", anchor, eye));
sprites.build();
scene.sprites = &sprites;      // обязан пережить сцену; текстуры — тоже
```

> **Светящиеся спрайты не освещают сцену.** `LightSet` собирается из открытых
> эмиссивных граней **воксельного мира** и только из них. Уголёк с `emission`
> светится сам и попадает в отражения, но явной выборкой не сэмплируется.
> Это осознанно: частицы украшают кадр, а не освещают его, и тысяча крошечных
> источников в списке обошлась бы дороже, чем стоит их вклад.

## font.hpp

```cpp
bool loadFromSource(const AssetSource&, const std::string& path = kMinecraftAscii, error);
bool loadFromPng(const uint8_t*, size_t, error);
void useBuiltin();

bool loaded() const;
bool isBuiltin() const;
const Texture& texture() const;

Glyph glyph(unsigned char code) const;   // uvMin, uvMax, width, advance, blank
int   cellPixels() const;                // высота строки в пикселях глифа
float measure(const std::string&) const; // суммарный вынос, без хвостового зазора
```

Атлас — сетка 16×16 квадратных ячеек. Это в точности
`assets/minecraft/textures/font/ascii.png`: 128×128, **один бит на пиксель**,
две палитровые записи (обе белые) и `tRNS`, делающий индекс 0 прозрачным. Наш
декодер PNG читает индексированные картинки глубины 1 с палитровой альфой, так
что игровой шрифт достаётся даром — ни строки нового кода.

**Ширины глифов в файле не записаны.** Игра выводит их, находя самый правый
столбец ячейки, в котором есть чернила; мы делаем так же. Без этого каждая
буква была бы моноширинной в восемь пикселей, и `i` сидела бы посреди лужи.

`useBuiltin()` даёт компактный шрифт 5×7 — заглавные, цифры и пунктуация,
нарисованные прямо в `font.cpp` строками из `#` и `.`, чтобы неверный пиксель
был виден в исходнике. Строчные обслуживаются заглавными формами. Это тот же
принцип, по которому сцена без ассетов рендерится плоской палитрой: деградирует,
а не ломается.

## text.hpp

```cpp
namespace text {
std::vector<Sprite> build(const Font&, const std::string&, Vec3 position, const TextStyle& = {});
std::vector<Sprite> facing(const Font&, const std::string&, Vec3 position, Vec3 target, const TextStyle& = {});
Vec2 measure(const Font&, const std::string&, const TextStyle& = {});
}
```

| `TextStyle` | По умолчанию | Смысл |
|---|---|---|
| `height` | `0.5` | Высота строки в блоках; ячейка глифа ложится ровно в неё |
| `color` | `1` | Линейный цвет. Рукописный оборачивай в `srgbToLinear` |
| `emission` | `0` | Выше нуля надпись светится — но сцену не освещает |
| `align` | `Center` | `Left`, `Center`, `Right` |
| `lineSpacing` | `1.25` | Кратно `height`, между базовыми линиями |
| `yawDegrees` / `pitchDegrees` | `0` | Ориентация **всей надписи**. Ноль смотрит в +Z |
| `alphaCutoff` | `0.5` | Вырез, которым глиф и становится глифом |
| `doubleSided` | `true` | Сзади читается зеркально, как табличка в игре |

Ориентация принадлежит **надписи, а не буквам**. Развернуть каждый глиф к
камере по отдельности — значит закрутить каждый на месте, оставив их
растянутыми вдоль исходной оси: читаемые буквы в нечитаемой строке. Поэтому
раскладка сразу идёт в повёрнутом базисе — `right` и `up` берутся из yaw и
pitch самой надписи, и перо шагает по ним.

Перевод строки начинает новую строку; пробел — движение пера, а не геометрия,
и спрайта не порождает.

## scatter.hpp

Частица в статичной сцене — это **застывшее мгновение**. Эмиттера и симуляции
нет и не нужно: кадру нужен результат — снег уже в воздухе, угли уже поднялись,
пыль уже висит в луче. Эти функции ставят мгновение напрямую, а интересный
параметр — форма объёма, а не скорость.

```cpp
std::vector<Sprite> inBox(Vec3 lo, Vec3 hi, int count, uint32_t seed, const ParticleStyle& = {});
std::vector<Sprite> inSphere(Vec3 centre, float radius, int count, uint32_t seed, ...);
std::vector<Sprite> inBeam(Vec3 from, Vec3 direction, float length, float radius, int count, uint32_t seed, ...);

std::vector<Sprite> onSurface(const World&, IVec3 lo, IVec3 hi, int topY, int count,
                              uint32_t seed, float heightAbove = 0.15f, ...);
std::vector<Sprite> above(const World&, IVec3 lo, IVec3 hi, BlockId id, float height,
                          int perBlock, uint32_t seed, ...);

void removeInsideSolid(std::vector<Sprite>&, const World&);
```

| `ParticleStyle` | По умолчанию | Смысл |
|---|---|---|
| `size` | `0.12` | Ребро в блоках |
| `sizeJitter` | `0.4` | Доля, на которую размер гуляет — чтобы россыпь не читалась штампом |
| `texture` | `nullptr` | Без неё квад заливается `tint` |
| `tint` / `emission` | `1` / `0` | Линейные |
| `randomYaw` / `randomRoll` | `true` | Случайный разворот |

`inSphere` сэмплирует по объёму отбраковкой, а не радиусом напрямую — иначе всё
сбилось бы к центру. `inBeam` берёт корень из радиуса по той же причине.
`above` селит плотность к источнику как `u²`, потому что так и выглядит султан.

`removeInsideSolid` выбрасывает спрайты, чей центр оказался внутри блока,
задерживающего свет: объёмные россыпи о мире не знают, и это способ не получить
пылинки, замурованные в рельеф.

> **Пыль лучше разворачивать к камере.** Оставленные под случайными углами,
> частицы показывают лучу то ребро, то теневую сторону, и столб света так и не
> собирается в столб. `randomYaw = false` плюс `aimAt(motes, eye)` после
> россыпи — тот же приём заморозки, что у надписи. Проверено на сцене
> `sprites`: без него шахты света не читаются вовсе.

## Что это добавляет в кадр

Спрайты проходят через ту же
[единую точку пересечения](architecture.md#ключевое-решение-единая-точка-пересечения),
что блоки и сущности, и разрешаются в тот же `SceneHit`. Поэтому:

- пыль в шахте освещена **тем самым** солнцем, и темнеет в двух блоках оттуда,
  где луч перекрыт крышей;
- непрозрачный глиф отбрасывает тень, а прозрачный тексель — нет;
- надпись попадает в отражение воды;
- уголёк с `emission` светится и виден в отражении.

Ни одна из этих строчек не написана отдельно — всё это следствия того, что
спрайт разрешается в обычное попадание.

## Чего нет

- **Вьюпорт спрайтов не показывает.** `buildWorldMesh` и `buildEntityMesh`
  есть, `buildSpriteMesh` — нет. Для расстановки камеры это не мешает, но
  частицы в предпросмотре не видны.
- **Спрайты не в списке источников** — см. врезку выше.
- **BVH не перестраивается инкрементально.** `add` сбрасывает дерево целиком,
  `build` строит заново. Сцена собирается один раз, перестраивать нечего.
- **Нет объёмного рассеяния.** Пыль — это дискретные квады, а не среда.
  Настоящий однократный рассеиватель дал бы гладкий столб вместо россыпи искр,
  и это отдельная крупная работа в интеграторе.
