# API: engine/prop

[← README](../README.md) · [core](api-core.md) · [world](api-world.md) · [scene и render](api-render.md) · [gpu](api-gpu.md) · [assets и entity](api-assets.md) · [sprite](api-sprite.md) · [prop](api-prop.md) · [rig](api-rig.md) · [anim](api-anim.md) · [physics](api-physics.md) · [script](api-script.md) · [video](api-video.md)

Предметы и пропы — маленькие плотные воксельные сетки, размещаемые
преобразованием, а не координатами решётки. Два источника: предметы из игры и
собственные модели.

Ассеты необязательны: без них доступны все способы кроме игровых предметов.

---

## Почему это не World

`World` — хеш-карта чанков 16³, чьи id индексируют глобальный реестр. Это верно
для рельефа и неверно для меча высотой в шестнадцать вокселей, которому нужна
сотня произвольных цветов, ни с кем не разделяемых.

Плюс главное: **штамповать проп в мир значит прибить его к решётке.** Ни
свободного поворота, ни размера меньше блока — а предмет ростом в шестнадцать
вокселей занимает один блок, то есть каждый его воксель в шестнадцать раз
мельче блока. Ровно то, ради чего всё и делалось.

Поэтому проп — маленькая, плотная сетка со своей палитрой, размещаемая
жёстким преобразованием с равномерным масштабом.

## voxel_model.hpp

```cpp
struct VoxelMaterial { Vec3 albedo, emission; float roughness, metallic; };
struct VoxelHit { float t; Vec3 position, normal; IVec3 voxel; uint16_t material; };

void  resize(IVec3 dims);          // очищает
void  set(IVec3 v, uint16_t material);
uint16_t at(IVec3 v) const;        // kEmpty == 0

uint16_t addMaterial(const VoxelMaterial&);   // одинаковые складываются
const VoxelMaterial& material(uint16_t) const;

void trim();                       // ужать до занятой коробки

bool trace(Vec3 origin, Vec3 direction, float tMin, float tMax, VoxelHit&) const;
bool occluded(Vec3 origin, Vec3 direction, float tMin, float tMax) const;
```

Индекс 0 всегда означает «пусто», поэтому запись палитры никогда не ноль.

`addMaterial` **складывает одинаковые материалы**. Это не оптимизация ради
оптимизации: выдавленная текстура предмета просит по материалу на тексель, и
большинство из них — один и тот же цвет.

`trim` обязателен для предметов: текстура предмета в основном пустая, и без
него габариты каждого пропа были бы полным кубом 16×16×16.

**Обход — одноуровневый DDA.** Двухуровневый в мире существует, чтобы
пропускать пустые чанки; в сетке такого размера пропускать нечего.

> `direction` **не обязан** быть единичным. Вызывающий масштабирует его тем же
> множителем, что и пространство, — именно это и сохраняет параметр луча
> одинаковым по обе стороны преобразования.

## prop_set.hpp

```cpp
struct Prop {
    enum class Anchor { BottomCentre, Centre, Min };

    const VoxelModel* model = nullptr;   // обязан пережить набор
    Vec3  position{};
    float yawDegrees, pitchDegrees, rollDegrees;
    float voxelSize = 1.0f / 16.0f;
    Anchor anchor = Anchor::BottomCentre;
    Vec3  tint{1}, emissionScale{1};
};
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `voxelSize` | `1/16` | Мировых единиц на воксель. Предмет в 16 вокселей встаёт ровно в блок |
| `anchor` | `BottomCentre` | Где `position` сидит на модели: подошва, центр или собственный угол |
| `tint` | `1` | Умножает альбедо палитры — одна модель, много цветов |
| `emissionScale` | `1` | То же для излучения |

```cpp
void add(const Prop&);
void add(const std::vector<Prop>&);
void build();                       // BVH; до него набор инертен

bool intersect(const Ray&, float maxDistance, PropHit&) const;
bool occluded(const Ray&, float maxDistance) const;
bool bounds(Vec3& lo, Vec3& hi) const;

size_t   size() const;
uint64_t voxelCount() const;        // честная мера веса набора
const Bvh& bvh() const;
```

`PropHit` несёт полный материал, **включая `metallic`** — поэтому золотой
слиток это настоящий проводник GGX, а не жёлтый диффузный кирпич. Проп никогда
не среда: преломление отслеживается по блоку, внутри которого идёт луч, а проп
не блок.

Масштаб **равномерный** намеренно. Неравномерный растянул бы локальное
направление луча по-разному вдоль осей, и параметр `t` перестал бы значить одно
и то же по обе стороны преобразования.

Сто пропов, делящих одну модель, стоят памяти одной модели: набор хранит
указатели и матрицы.

## item.hpp

```cpp
void buildModel(const Texture&, VoxelModel& out, const ItemOptions& = {});
bool loadModel(const AssetSource&, const std::string& path, VoxelModel&, const ItemOptions& = {}, error);
bool loadByName(const AssetSource&, const std::string& name, VoxelModel&, const ItemOptions& = {}, error);
```

Предмет в игре — плоский спрайт 16×16. То, что видно в руке или на земле, — этот
спрайт **выдавленный**: каждый непрозрачный тексель становится коробочкой
глубиной в пару текселей. Для воксельного рендерера это не приближение чужой
модели, а буквально та же конструкция.

Все 587 текстур предметов в jar 1.20 — индексированные PNG 16×16, которые наш
декодер уже читает. Модельный JSON игры не нужен вовсе.

| `ItemOptions` | По умолчанию | Смысл |
|---|---|---|
| `depthTexels` | `2` | Толщина. У сгенерированной моделью игры грани на 7/16 и 9/16 |
| `alphaCutoff` | `0.5` | Ниже — не часть предмета |
| `trim` | `true` | Ужать до занятой коробки |
| `roughness` / `metallic` | `1` / `0` | На каждый воксель |
| `emission` | `0` | Линейное, для светящихся |

> Металличность **не угадывается**. В текстуре ничего не написано о том, какой
> предмет металлический, а вывод по имени файла — это догадка, которая рано или
> поздно ошибётся. Задаёт вызывающий.

```cpp
item::ItemOptions gold;
gold.metallic = 1.0f;
gold.roughness = 0.18f;
item::loadByName(source, "gold_ingot", model, gold);
```

Анимированные текстуры (полоса кадров) обрезаются до первого кадра.

## voxelize.hpp

### fromWorld — захват готового

Главный способ. Всё в `shape::` уже строит воксели — эллипсоиды, цилиндры,
линии, эрозия, буфер обмена, — но строит их в `World`, привязанный к решётке.
Захват превращает эту работу в проп, который поворачивается свободно,
масштабируется во что угодно и штампуется сотней копий.

```cpp
World scratch;
shape::cylinder(scratch, {12, 0, 12}, {0, 1, 0}, 7.0f, 18.0f, palette::OakPlanks);
shape::cylinder(scratch, {12, 3, 12}, {0, 1, 0}, 5.6f, 16.0f, block::Air);
shape::torus(scratch, {12, 3.5f, 12}, {0, 1, 0}, 7.0f, 0.9f, palette::IronBlock);

VoxelModel barrel = voxelize::fromWorld(scratch, {0, 0, 0}, {24, 20, 24});
```

| `CaptureOptions` | По умолчанию | Смысл |
|---|---|---|
| `skipTransmissive` | `true` | Вода и стекло пропускаются: в мире они среды, а проп сред не знает |
| `textures` | `nullptr` | С библиотекой воксель берёт среднее по шести граням вместо плоского альбедо |
| `trim` | `true` | Ужать |

> **У вокселя один материал, а не шесть.** Захваченный блок травы будет одного
> цвета, а не зелёным сверху и коричневым с боков. Это тот же размен, что
> делает MagicaVoxel, и для пропов он верный: материалы по граням ушестерили бы
> обращения к палитре ради случая — захваченного блока, обязанного сохранить
> разницу граней, — с которым сам мир справляется лучше.

### fromLayers — нарисованное текстом

Для мелочи, которую примитивом не описать: кружка, книга, фонарь.

```cpp
VoxelModel lantern = voxelize::fromLayers({
    {".###.", "#####", "#####", "#####", ".###."},   // y0
    {".....", ".#~#.", ".~~~.", ".#~#.", "....."},   // y1
    {".###.", "#####", "#####", "#####", ".###."},   // y2
}, {{'#', iron}, {'~', glass}});
```

`layers[y][z][x]`: слой на каждый Y снизу вверх, в слое строки вдоль +Z, в
строке символы вдоль +X. `.` и пробел — пусто, символа нет в ключе — пропуск.

Рисунок, а не таблица байт, по той же причине, что и встроенный шрифт: неверный
воксель виден в исходнике.

### Прямая запись

Модель — обычная сетка, поэтому автором может быть что угодно, умеющее решить
«твёрдо или нет»:

```cpp
VoxelModel crystal;
crystal.resize({9, 19, 9});
uint16_t core = crystal.addMaterial(glowing);

for (int y = 0; y < 19; ++y) {
    float radius = 4.0f * std::pow(1.0f - float(y) / 18.0f, 0.6f);
    // ... заполнить диск радиуса radius
}
crystal.trim();
```

## Что это добавляет в кадр

Пропы проходят через ту же
[единую точку пересечения](architecture.md#ключевое-решение-единая-точка-пересечения),
что блоки, сущности и спрайты, и разрешаются в тот же `SceneHit`. Поэтому меч
отбрасывает тень на скамью, золотой слиток отражает окружение как металл, а
светящееся стекло фонаря видно в отражениях — ничего из этого не написано
отдельно.

## Чего нет

- **Вьюпорт пропы не показывает** — как и спрайты, `buildPropMesh` нет.
- **Пропы не в списке источников.** Светящийся кристалл светится, но сцену не
  освещает: `LightSet` строится из граней воксельного мира. Если фонарь должен
  реально светить, поставь рядом `palette::Glowstone` — так делает `scene_props`.
- **Проп не может быть средой.** `transmission` у материала вокселя нет:
  отслеживание среды в трассировщике идёт по `BlockId`, внутри которого луч, а
  проп не блок. Стекло пропа — непрозрачное крашеное стекло.
- **Один материал на воксель**, не шесть. См. врезку выше.
- **BVH не перестраивается инкрементально:** `add` сбрасывает дерево, `build`
  строит заново.

> Проп, который должен ехать с рукой персонажа, ставится не отсюда, а
> `VoxelAttachment` — см. [api-assets.md](api-assets.md#entityattachhpp).
