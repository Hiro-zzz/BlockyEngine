# Скриптовый слой

[← README](../README.md) · [core](api-core.md) · [world](api-world.md) · [scene и render](api-render.md) · [gpu](api-gpu.md) · [assets и entity](api-assets.md) · [sprite](api-sprite.md) · [prop](api-prop.md) · [rig](api-rig.md) · [anim](api-anim.md) · [physics](api-physics.md) · [script](api-script.md) · [video](api-video.md)

Свой язык для геймплейного слоя песочницы. Файлы `.bly`, живут в
`scenes/scripts/`.

Он существует ради одного свойства: **цикл правки без пересборки**. Сцены как
отдельные исполняемые файлы — правильное решение для кадра, который считают
один раз, но в песочнице инструмент, требующий пересборки и рестарта с потерей
мира, не итерируется. Скрипт перезагружается, мир остаётся стоять.

Почему не Lua — две причины, и только вторая про зависимости:

- **Векторы здесь значения.** Любой скрипт этого движка занят векторной
  арифметикой, а во встроенном языке это аллокация и диспетчеризация по
  метатаблице на каждую операцию. `Value` несёт `Vec3` внутри себя, поэтому
  `a + b * 2` не аллоцирует ничего. Язык под свою задачу стоит дороже общего.
- Всё остальное в движке своё, а VM меньше уже написанного здесь H.264.

## Язык

```
// Комментарий до конца строки.

let n = 3                      // объявление; присваивание без let — ошибка
let name = "crate"
let p = vec(1, 2.5, -3)
let xs = [1, 2, 3]
let m = {a: 1, b: 2}           // порядок вставки сохраняется

fn add(a, b) { return a + b }  // функции — значения, замыкания работают

if n > 2 { ... } else if n == 2 { ... } else { ... }
while n > 0 { n = n - 1 }
for i in range(5) { ... }      // по списку или по ключам карты
break / continue / return

on ready { ... }               // обработчик события от хозяина
on tick(dt) { ... }
```

Терминаторы не нужны; `;` разрешена и ничего не значит.

| | |
|---|---|
| Типы | `nil`, `bool`, `number` (double), `vec`, `string`, `list`, `map`, функция, `handle` |
| Истинность | ложны только `nil` и `false`. **Ноль истинен** — иначе `if count` значило бы не то же, что `if count != 0`, ровно когда счётчик равен нулю |
| Операторы | `+ - * / %`, сравнения, `and or not`, `==` `!=` |
| Векторы | `v + v`, `v * число`, `v * v` покомпонентно, `v / число`, `-v`, поля `.x .y .z` |
| Строки | `+` с чем угодно приводит к строке |

**Векторы неизменяемы.** `p.x = 1` — ошибка: запись пришлось бы протаскивать
обратно в то, что породило `p`, а у `f().x = 1` протаскивать не во что.
Пересоберите: `p = vec(1, p.y, p.z)`.

### Единственная неоднозначность грамматики

После `if`, `while` и `in` символ `{` открывает тело, а не карту. Отличить их
без догадки нельзя, поэтому карта там пишется в скобках — так же и по той же
причине поступает Go:

```
for k in ({a: 1, b: 2}) { ... }
```

Сообщение об ошибке говорит об этом прямо, а не «ожидалось выражение».

## Что даёт ядро

`print` `type` `str` `num` `assert` · `len` `push` `pop` `keys` `has` `remove`
`range` · `vec` `length` `normalize` `dot` `cross` `distance` · `abs` `floor`
`ceil` `round` `sqrt` `sin` `cos` `atan2` `pow` `min` `max` `clamp` `radians`
`degrees` `rand` · константа `pi`.

`rand` берёт из генератора интерпретатора с постоянным зерном: скрипт,
раскидывающий сто ящиков случайно, раскидывает **те же сто** при каждом
запуске. То же соображение, которым выше по стеку защищён дубль.

## Что даёт песочница

`engine/script/bindings.hpp` — единственный файл в `script/`, знающий про
воксели.

| | |
|---|---|
| Мир | `setblock(p, id)`, `getblock(p)`, `fillbox(a, b, id)`; имена блоков как глобальные — берутся **из палитры мира**, поэтому блок зовут так, как его зарегистрировали: `stone`, `oak_log`, `grass_block`… |
| Тела | `spawn(имя, позиция [, тинт])` → handle, `pos`, `velocity`, `setvelocity`, `setspin`, `turn(тело, ось, градусы)`, `asleep`, `bodycount` |
| Связи | `weld(a, b, точка)`, `ballsocket(a, b, точка)`, `hinge(a, b, точка, ось)`, `rope(a, b, точкаA, точкаB [, длина])`, `rod(...)` — то же, но двусторонняя, `breakable(связь, импульс)`, `broken(связь)` |
| Привод | `damp(связь, сила)` — трение в свободных направлениях; `motor(петля, скорость, момент)`, `unmotor(петля)`; `setlength(связь, м)`, `jointlength(связь)` |
| Персонажи | `spawnentity(скин, позиция [, поворот])` → handle, `place`, `face`, `facing`, `pose(e, сустав, x, y, z)`, `stride`, `wave`, `rest`, `entitycount` |

Вторым телом можно передать `nil` — это привязка к неподвижному миру.

Скрипт держит **handle**, а не указатель, поэтому пережившая шаг ссылка не
может смотреть в освобождённую память; худшее, что она может, — назвать то,
чего больше нет, и каждая привязка это проверяет.

### Трение, моторы и поршни

`damp` — сопротивление тому, что связь оставляет **свободным**: оси у петли,
всем трём вращениям у шарнира, линии у верёвки и штанги. У сварки свободного
нет, поэтому там оно ничего не делает. Без трения петля — маятник без потерь:
физика верная, для песочницы бесполезная, потому что остров никогда не уснёт.

`motor` есть только у петли — это и есть ведущая ось: колесо, лебёдка,
поворотный узел. Момент ограничен не для красоты: мотор без предела набирает
любую скорость за шаг и превращается в рычаг, двигающий мир. Мотор со
скоростью 0 — тормоз, поэтому при работающем моторе трение отступает.

### Персонажи — не тела

Проп принадлежит солверу; персонаж принадлежит **скрипту**. Сущность не
симулируется, её *ставят и гнут*, поэтому её состояние живёт в песочнице, а
хозяин каждый кадр уплощает список в `EntitySet` — ровно как делает с пропами.

Суставы называются словами, а не номерами: `pose(p, "head", 0, 30, 0)`.
Доступны `root`, `body`, `head`, `rightarm`, `leftarm`, `rightleg`, `leftleg`;
неизвестное имя перечисляет существующие. `pos` отвечает и за тело, и за
сущность — handle сам говорит, что это.

Скин регистрирует хозяин. Игровые файлы не нужны: `demo::loadDemoSkin` берёт
`assets/skins/charlie.png`, а если его нет — строит фигуру процедурно. Движок
всегда умел рендерить без ассетов, и песочница, требующая jar ради человечка,
это свойство бы сломала.

**Поршня как отдельного типа связи нет.** Поршень — это штанга, длину которой
кто-то ведёт, и этот кто-то — `on tick`:

```
on tick(dt) {
    setlength(ram, 1.6 + sin(elapsed * 1.1) * 0.9)
}
```

## Перезагрузка

Три правила, и это и есть весь дизайн слоя:

- **Синтаксическая ошибка не меняет ничего.** Новый текст разбирается до того,
  как что-либо выбрасывается, и битый файл оставляет работать предыдущую
  программу. Тот, кто правит инструмент с открытым миром, сохраняет
  сломанный файл каждые несколько минут; это должно стоить сообщения, а не
  сессии.
- **Состояние живёт на стороне хозяина.** Тела, связи, блоки. Скрипт
  описывает поведение, а его куча освобождается при перезагрузке целиком —
  это же снимает вопрос отсутствующего сборщика мусора.
- **Привязки переустанавливаются, а не запоминаются.** Хозяин даёт `onBind`,
  который зовут при каждой загрузке: одно место говорит, что скрипту
  доступно, и разойтись двум загрузкам негде.

`reloadIfChanged()` сравнивает **содержимое**, а не время правки: файл
размером в страницу читать бесплатно, а время модификации на удивление
ненадёжно между редакторами и файловыми системами.

## Что скрипт не может сломать

- **Ошибка выполнения не роняет сессию.** Она докладывается с номером строки,
  обработчик прерывается, мир продолжает считаться.
- **Бесконечный цикл не вешает игру.** Каждая инструкция тратит единицу
  бюджета вызова; `while true { }` выбирает его и сообщает о себе.
- **`fillbox` отказывается** заполнять больше четырёх миллионов блоков — у
  единственной привязки, способной на неограниченную работу, своя защита.

## Чего нет

Сборщика мусора: значения-числа и векторы лежат внутри `Value`, а строковые
литералы разделяются (строки неизменяемы, поэтому одного объекта хватает —
без этого `pose(p, "head", ...)` в покадровом обработчике аллоцировал строку
на каждый тик). Поэтому обычный покадровый обработчик не аллоцирует вовсе; но
тот, что строит список каждый кадр, будет расти до перезагрузки.

> **Долго это было верно только про объекты.** Области видимости тоже лежат в
> куче, и, в отличие от объектов, скрипт не выбирает, брать их или нет: по
> одной на вызов, на блок, на ветку, на оборот цикла. Обработчик, который
> только складывал числа, набирал 56 МБ за десять минут при 60 Гц — а тест,
> который должен был это ловить, считал объекты, и объекты как раз не росли.
>
> Теперь область возвращается в свободный список, когда её блок кончился и её
> никто не захватил. Вопрос «а вдруг захватил» решается не общим обходом
> достижимости, а тем единственным способом, которым область умеет пережить
> свой блок: стать окружением замыкания, своим или чьего-нибудь потомка.
> Замыкание — это объект вида `Function`, поэтому достаточно сравнить счётчик
> созданных функций на входе в блок и на выходе. Не изменился — держать
> область некому. Ошибка возможна только в безопасную сторону: блок, сделавший
> замыкание, оставляет свою область навсегда, и это та самая цена отсутствия
> сборщика — только платят её теперь блоки с замыканиями, а не все подряд.
>
> Замерено на том же обработчике: 396 001 область за десять минут стала
> шестью, и рост рабочего множества — нулевым. `test_script` требует, чтобы
> девятьсот тиков не потребовали ни одной области сверх тех, что понадобились
> первым ста, и отдельно — чтобы замыкание, сделанное внутри оборота цикла,
> по-прежнему помнило именно свой оборот.

Байткодной VM:
дерево обходится напрямую, и это осознанно — тяжёлое живёт в C++, куда скрипт
не заходит; шов проведён так, что заменить `Interpreter` можно, не трогая ни
парсер, ни привязки. Модулей и `import`. Создания геометрии из скрипта:
модели регистрирует хозяин.

## Живая перезагрузка в окне

`scene_live` держит окно с идущей физикой и опрашивает файл скрипта каждый
кадр. Правишь `.bly` в соседнем окне, сохраняешь — мир пересобирается, не
перезапуская процесс, не пересоздавая GL-контекст и **не сдвигая камеру**.
Синтаксическая ошибка стоит строки в заголовке окна и ничего больше.

Что мир пересобирается целиком — политика *этой сцены*, а не языка: скрипт
здесь владеет содержимым мира, поэтому перезагрузка начинает с пустого.
Иначе правка числа добавила бы вторую конструкцию рядом с первой.

Шов во вьюпорте — `ViewportSettings::onFrame`: покадровый вызов, после
которого кэш чанков перестраивает только то, что хозяин действительно тронул.
