## camera.hpp

Ортография здесь полноправный режим, а не довесок: классический вид «рендер
постройки» — это изометрическая ортографическая проекция, и именно она
заставляет сцену читаться диорамой, а не скриншотом.

```cpp
void lookAt(Vec3 eye, Vec3 at, Vec3 upHint = {0, 1, 0});

Ray generateRay(float u, float v) const;              // (0,0) — левый верх
Ray generateRay(float u, float v, Vec2 lens) const;   // lens — точка в единичном диске

static Camera isometric(Vec3 centre, float heightUnits,
                        float distance = 256, float yawDegrees = 45);

Mat4 viewMatrix() const;
Mat4 projectionMatrix(float zNear = 0.05f, float zFar = 2048.0f) const;
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `projection` | `Perspective` | `Perspective` или `Orthographic` |
| `fovY` | `50°` | Только перспектива |
| `orthoHeight` | `32.0` | Только ортография: сколько блоков видно по вертикали |
| `aspect` | `16:9` | Рендерер выставляет сам по разрешению |
| `aperture` | `0.0` | Радиус линзы в мировых единицах. Ноль — всё резко |
| `focusDistance` | `10.0` | Расстояние до плоскости фокуса |

`isometric` даёт настоящую изометрию: наклон `atan(1/√2) ≈ 35.264°`, при
котором три видимые грани куба проецируются в равные площади.

### Глубина резкости

Тонкая линза. Точка на плоскости фокуса остаётся на месте — луч
переприцеливается из смещённой точки линзы в ту же точку фокуса. Всё, что вне
этой плоскости, попадает в диск вместо точки: это и есть размытие.

```cpp
scene.camera.aperture = 0.5f;          // несколько сантиметров хватает
scene.camera.focusOn({-6.0f, 14.0f, 6.0f});   // вместо угадывания расстояния
```

## scene.hpp

Всё, что нужно рендереру для кадра. Ассеты и сущности необязательны: сцена без
них рисуется плоской палитрой.

```cpp
struct Scene {
    World    world;
    Camera   camera;
    SunLight sun;
    Sky      sky;

    const BlockTextureLibrary* blockTextures = nullptr;   // только указатели —
    const EntitySet*           entities      = nullptr;   // обязаны пережить сцену
    const SpriteSet*           sprites       = nullptr;   // и пройти build()
    const PropSet*             props         = nullptr;   // то же

    MaterialStyle materialStyle;                          // identity по умолчанию

    float ambientStrength = 1.0f;

    bool  overrideBackground = false;
    Vec3  background{0.0f};

    Vec3 missColor(Vec3 direction) const;
    void frameAll(float heightMargin = 1.15f, float yawDegrees = 45.0f);
};
```

`frameAll` ставит изометрическую камеру по габаритам всего, что есть в мире.

| `SunLight` | По умолчанию | Смысл |
|---|---|---|
| `direction` | — | Направление **к солнцу**, нормированное |
| `color` | тёплый белый | Цвет |
| `intensity` | `4.2` | Освещённость при нормальном падении |
| `angularRadiusDegrees` | `0.6` | Настоящее солнце — около 0.53°. Больше — мягче тени |

`Sky` — аналитическое трёхцветное небо: `zenith`, `horizon`, `ground`,
`intensity`. Дёшево, управляемо и достаточно, чтобы освещать сцену.
Физическую модель можно поставить на его место, не трогая ничего, что зовёт
`sample()`.

> Ортокамера пускает параллельные лучи, поэтому промах даёт ровно один цвет.
> Такие сцены обязаны задать `overrideBackground` и `background`.

## intersect.hpp

Один запрос, которым пользуются оба рендерера. Воксельный мир, коробки
сущностей, квады спрайтов и сетки пропов сводятся здесь в единое попадание с
**уже готовым материалом** — текстуры выбраны, тинты применены. Секунд этот
запрос не знает: дубль для него — просто снова та же сцена.

```cpp
bool intersectScene(const Scene&, const Ray&, float maxDistance, RayFilter, SceneHit&);
Vec3 sceneTransmittance(const Scene&, const Ray&, float maxDistance);
```

Фильтр уходит в воксельный обход, а сущности проверяются **всегда** —
персонаж может стоять по колено в воде.

`SceneHit` помимо `t`, точки и нормали несёт материал: `albedo`, `emission`,
`roughness`, `metallic`, `transmissive`, `ior`, `absorption`. Плюс
происхождение: `isBlock`, `blockId`, `block`, `blockNormal`, `axis` —
воксельные данные нужны прямому рендеру для углового AO, а у сущности такого
окружения нет.

## direct.hpp

Быстрый предпросмотр: луч камеры, теневой луч к солнцу, небо как рассеянный
свет и угловое AO в стиле smooth lighting. Непрямых отскоков нет — это и есть
разница с path tracer. Прозрачные среды проходятся насквозь без преломления,
но с поглощением по толще и френелевским бликом неба.

```cpp
Image renderDirect(const Scene&, const DirectSettings&, RenderStats* = nullptr);
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `samplesPerPixel` | `4` | У вокселей нет кривых силуэтов, 4–16 хватает |
| `maxDistance` | `2048` | Дальность луча |
| `ambientOcclusion` | `true` | Угловое AO по восьми соседям грани |
| `aoStrength` | `1.0` | Сила AO |
| `softShadows` | `true` | Учитывать угловой размер солнца |
| `flatLighting` | `false` | Отключить свет вовсе: одна яркость на направление грани, ни теневых лучей, ни выборки неба. Это и есть режим «без шейдеров», а не ухудшенный предпросмотр |
| `threads` | `0` | 0 — по числу аппаратных потоков |
| `seed` | `1` | Зерно ГПСЧ |

## pathtrace.hpp

Однонаправленный трассировщик с явной выборкой источников. Сходимость идёт как
`1/√N`: переход с 64 сэмплов на 256 **вдвое** уменьшает шум, а не вчетверо.

```cpp
Image renderPath(const Scene&, const PathSettings&,
                 RenderStats* = nullptr, RenderTargets* aovs = nullptr);
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `samplesPerPixel` | `64` | С шумоподавителем 64 хватает; без него нужно 200–400 |
| `maxBounces` | `8` | Жёсткий потолок длины пути |
| `rouletteStartBounce` | `4` | С какого отскока включается русская рулетка |
| `clampIndirect` | `12.0` | Отсечение «светлячков». Слегка гасит каустики. 0 — выключить |
| `progress` | `true` | Печатать процент в stdout |

### Как считается свет

- **Солнце** сэмплируется явно, выборкой по конусу. Плотность конуса и
  нормировка яркости сокращаются точно, оставляя `f · cos · освещённость`.
- **Светящиеся блоки** собираются в список площадных источников: каждая
  *открытая* грань — отдельный источник, выбор пропорционален мощности. Грань,
  замурованная в камень, в список не попадает.
- **Небо** явно не сэмплируется — приходит через отскоки. Для большого
  источника это сходится нормально.
- **Двойного учёта нет:** после диффузного отскока излучение, найденное лучом
  BSDF, не добавляется — его уже посчитала явная выборка. После зеркального —
  добавляется.

### RenderTargets (AOV)

```cpp
struct RenderTargets {
    Image color, albedo, normal;
    std::vector<float> depth;   // отрицательная на промахе
    int width, height;
};
```

Описывают **первую поверхность**, которую увидел пиксель, проходя насквозь
стекло и воду: альбедо преломляющей границы ничего не говорит о том, на что
смотрит пиксель. Нужны шумоподавителю.

## bsdf.hpp и lights.hpp

Грани вокселей строго плоские и осевые, поэтому геометрическая и затеняющая
нормали совпадают — ни один из обычных костылей против артефактов терминатора
не нужен.

```cpp
bsdf::Frame(Vec3 normal);                          // локальный базис, нормаль = +Z
Vec3  bsdf::fresnelSchlick(float cosTheta, Vec3 f0);
float bsdf::fresnelDielectric(float cosThetaI, float eta);   // 1 при полном внутреннем отражении
bool  bsdf::refractRay(Vec3 incident, Vec3 normal, float eta, Vec3& out);
Vec3  bsdf::sampleGgxVndf(Vec3 wo, float alpha, float u1, float u2);
```

`sampleGgxVndf` сэмплирует распределение **видимых** нормалей (Heitz 2018) —
именно это не даёт скользящим углам взрываться светлячками.

```cpp
void LightSet::build(const World&);
bool LightSet::sample(Rng&, Vec3 point, Vec3& dir, float& dist,
                      Vec3& radiance, float& pdf) const;
```

`pdf` — плотность по телесному углу от точки.

## post/denoise.hpp

Edge-avoiding a-trous (Dammertz et al. 2010).

```cpp
Image denoise(const RenderTargets& targets, const DenoiseSettings& settings = {});
```

Без вспомогательных буферов вход возвращается **без изменений**, а не
размывается вслепую.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `iterations` | `5` | Каждая итерация вдвое шире; пять покрывают 80 пикселей, трогая по 25 отсчётов |
| `colorSigma` | `6.0` | Допуск по освещённости |
| `normalSigma` | `0.25` | Допуск по нормали |
| `depthSigma` | `0.6` | Допуск по глубине, в блоках |
| `albedoSigma` | `0.14` | Допуск по альбедо |
| `strength` | `1.0` | Ниже 1 оставляет немного зерна |
| `threads` | `0` | Ноль — по одному на аппаратный поток, как у `renderPath` |

**Строки делятся между рабочими, и делятся бесплатно.** Каждый проход читает
один буфер и пишет другой, поэтому две строки не смотрят друг другу в ответ:
разбиение не требует ни блокировок, ни порядка, и картинка не может зависеть
от числа рабочих. `test_procgen` требует **побитового** совпадения одного
потока с восемью, а не близости — допуск прятал бы ровно ту ошибку, которую
проверка ищет.

Замерено на 1280×720, пять итераций, шестнадцать логических ядер: 9.2 с в один
поток, 4.5 в два, 2.4 в четыре, дальше полка. Полка — потолок питания машины,
а не свойство фильтра. Абсолютные числа сравнимы только внутри одного прогона:
тот же однопоточный фильтр на той же машине даёт от 3.8 до 9.8 с в зависимости
от того, насколько она прогрета, тогда как многопоточный держится на 2.4.

> Долго был однопоточным, пока трассировщик над ним делил кадр на тайлы с
> самого начала. Разница стала заметной не сама по себе, а когда трассировка
> кадра фильма уехала на карту и стала стоить 3.4 с: фильтр, не подорожавший
> ни на йоту, вдруг оказался тем, чего ждут часы.

Два решения несут весь результат:

**Демодуляция.** Кадр делится на альбедо, фильтруется полученная
освещённость, текстура возвращается обратно. Фильтрация цвета напрямую стирает
текстуры блоков, какими бы умными ни были веса.

**Предсказание глубины по градиенту.** Глубина отсчёта сравнивается с
`centreDepth + dzdx·dx + dzdy·dy`, и допуск **не** растёт с шириной фильтра.

> Первая версия масштабировала допуск и на расстояние (`centreDepth * 0.1`), и
> на ширину фильтра. На дистанции 70 блоков это дало допуск в 11 блоков — две
> травяные террасы с одинаковой нормалью и одинаковым альбедо, отличающиеся
> только глубиной, сливались. Симптом, который легко пропустить: сырой кадр
> оказывается **резче** обработанного. `test_procgen` теперь падает, если это
> вернётся.

На синтетическом тесте: дисперсия падает примерно в 6700 раз, среднее
смещается меньше чем на 0.001, края альбедо и глубины держатся в пределах 0.05
от эталона.

## post/effects.hpp

Порядок жёсткий и не обсуждается: bloom в линейном свете до кривой, грейдинг
после bloom, но всё ещё в линейном, виньетка последней. Любой из этих эффектов
после тонмаппинга даёт мутный вид эффекта, наложенного на уже обрезанные
значения.

```cpp
void applyBloom(Image&, const BloomSettings&);
void applyGrade(Image&, const GradeSettings&);
void applyVignette(Image&, const VignetteSettings&);
void applyGrain(Image&, float amount, uint64_t seed = 1);
```

| `BloomSettings` | По умолчанию | Смысл |
|---|---|---|
| `threshold` | `1.2` | Яркость, выше которой пиксель светится |
| `knee` | `0.6` | Смягчает порог вместо обрыва на нём |
| `intensity` | `0.05` | Сколько подмешивается обратно |
| `levels` | `6` | Глубина пирамиды; каждый уровень вдвое шире |

| `GradeSettings` | По умолчанию | Смысл |
|---|---|---|
| `exposure` | `1.0` | Множитель; в стопах — `exp2` |
| `contrast` | `1.0` | Поворот вокруг среднего серого |
| `saturation` | `1.0` | Насыщенность |
| `temperature` | `0.0` | −1 к синему, +1 к янтарному |
| `lift` / `gain` | `0` / `1` | Прибавка к теням, множитель светов |

| `VignetteSettings` | По умолчанию | Смысл |
|---|---|---|
| `amount` | `0.3` | 0 — выключено, 1 — углы в чёрное |
| `radius` | `0.75` | Где начинается спад, в полудиагоналях |
| `softness` | `0.45` | Мягкость спада |

Bloom строится пирамидой: яркий проход, многократное уменьшение вдвое, затем
уровни складываются обратно. Широко, дёшево и без звона, который даёт одно
большое размытие.

## Стили рендера

Стиль — это не один переключатель, а **два шва**, и лежат они по разные
стороны от переноса света.

```
материал ──▶ [ materialStyle ] ──▶ перенос света ──▶ кадр ──▶ [ stylize ] ──▶ PNG
             scene/material_style        трассировка         render/post/stylize
```

Разделение не вкусовое. Блик — это свет, который надо проследить: его нельзя
домалевать поверх готового кадра, потому что он обязан попасть в отражения,
в тени и в буфер альбедо. И наоборот, полосы cel-шейдинга квантуют **итоговую**
освещённость, а она известна только когда кадр досчитан, — на каждом отскоке
решать нечего.

| Что | Где живёт | Почему именно там |
|---|---|---|
| Простой (без шейдеров) | `DirectSettings::flatLighting` | Это модель затенения, а не фильтр |
| Plastic | `Scene::materialStyle` | Блик надо трассировать |
| Cel | `post/stylize.hpp` | Квантуется готовая освещённость |
| Pixelated | `post/stylize.hpp` | Пикселей не существует, пока нет кадра |

## scene/material_style.hpp

Общесценная замена того, из чего сделаны поверхности. Применяется в
`intersectScene` — единственном месте, где материал разрешается, — поэтому
блоки, сущности, спрайты и пропы стилизовать по-разному невозможно.

```cpp
scene.materialStyle = MaterialStyle::plastic();
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `roughness` | `-1` | Отрицательное — оставить как было |
| `metallic` | `-1` | То же |
| `coat` | `0` | Сила **белого** диэлектрического покрытия |
| `coatRoughness` | `0.14` | Шероховатость покрытия: меньше — острее блик |
| `saturation` | `1.0` | На альбедо, **до** освещения |
| `gain` | `1.0` | То же |

Готовые: `realistic()` (тождество), `plastic()`, `matte()`.

> **Почему покрытие белое.** Проводник красит блик собственным цветом и
> диффузной доли не имеет вовсе; диэлектрик оставляет свой цвет и отражает
> цвет источника поверх. Покрасить блок металлическим ради глянца — получить
> первое там, где игрушке нужно второе.

> **Насыщенность здесь, а не в грейдинге.** Альбедо меняется до освещения,
> поэтому насыщенная красная стена подкрашивает соседнюю. Грейдинг готового
> кадра так не умеет — он уже не знает, что откуда отразилось.

Две вещи стиль не трогает намеренно: **преломляющую среду** (пластиковый океан
перестаёт быть океаном, а отслеживание среды завязано на `ior`) и **эмиссию**
(лампа остаётся лампой).

## post/stylize.hpp

```cpp
Image celShade(const RenderTargets&, const CelSettings& = {});
void  pixelate(Image&, const PixelateSettings& = {});
```

Оба работают в линейном свете, до тонмаппинга, — по той же причине, что и
bloom: квантовать значения, уже прошедшие кривую, значит полосить кривую, а не
свет.

### Cel

Приём тот же, что у шумоподавителя: поделить кадр на альбедо, квантовать
**освещённость**, вернуть текстуру обратно. Квантование цвета напрямую
разбивает на полосы саму текстуру, и каждая грань блока идёт горбылями.

Контур ищется в буферах глубины и нормали, а не в цвете, поэтому он обводит
геометрию и не замечает рисунка: стык двух каменных блоков на разной глубине
получает линию, нарисованный на одном из них раствор — нет.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `bands` | `4` | Ступеней освещённости; 0 или 1 — только контур |
| `range` | `1.0` | Освещённость, отображаемая в верхнюю полосу. **Обязателен к настройке**: полосы идут по 0..range, и на сцене ярче этого вся фигура садится в верхнюю ступень и выходит плоско-белой с контуром. Ключ силой около 4 хочет здесь примерно 2 |
| `shadowFloor` | `0.0` | Во что отображается нижняя полоса, долей от `range`. Ноль отправляет неосвещённое в честный чёрный — верно для жёсткой графики и неверно для персонажа: теневая сторона лица становится силуэтом. Около 0.3–0.4 — обычная амбиентная тень рисованного cel |
| `bandGamma` | `0.72` | Ниже 1 — ступени сгущаются в тенях |
| `highlightCeiling` | `3.0` | Выше — не полосить: лампа должна светить, а не упираться в верхнюю ступень |
| `depthThreshold` | `0.35` | Разрыв глубины в блоках, **против предсказания по градиенту** |
| `normalThreshold` | `0.35` | По `1 − dot(n₀, n₁)` |
| `outlineWidth` | `1` | Толщина в пикселях |
| `outlineColor` | чёрный | Цвет чернил |
| `outlineOpacity` | `0.85` | Непрозрачность |
| `saturation` | `1.0` | На полосатую освещённость, не на альбедо |

Ступени идут **от нуля до единицы**, а не по центрам интервалов. Центры
сохраняли бы среднее по кадру — свойство на слух более правильное и на деле
негодное: пиксель, не получивший света вовсе, поднимался бы до центра первой
полосы, а cel-кадр, у которого все тени одного тёмно-серого, теряет тот самый
контраст, ради которого затевался.

> Порог глубины сравнивается с предсказанием по градиенту, ровно как в
> шумоподавителе, и ровно по той же причине: пол, уходящий от камеры, меняет
> глубину быстрее порога на каждом пикселе, и ничто из этого не край.
> Без поправки такой пол обводит сам себя полосками.

> **Шумоподавитель — до cel, не после.** Полоса выбирается по каждому пикселю
> отдельно, поэтому остаточный шум разводит соседей по разным ступеням:
> получается спекл с резкими границами, куда хуже шума, из которого он вырос.

### Pixelate

| Поле | По умолчанию | Смысл |
|---|---|---|
| `factor` | `4` | Сторона ячейки в пикселях; разрешение кадра не меняется |
| `levels` | `0` | Ступеней на канал после укрупнения, 0 — не трогать цвет |

Ячейка **усредняется**, а не берётся точечно. Точечная выборка
трассированного кадра тащит шум одного пикселя на всю ячейку, и картинка
кишит светляками ровно того размера, на который теперь смотрит глаз.
Усреднение — бесплатное сглаживание для новой сетки.

Квантование цвета делается в sRGB и возвращается обратно: ступени по линейной
яркости почти целиком уходят на света, которых никто не различает, а теням
достаётся две-три.
